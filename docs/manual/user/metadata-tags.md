# Metadata, tags and comments

## Before you begin
Open **DAM > Assets**, then select an asset to open **Edit Asset**. You can also choose **Open details** from an asset preview. The tabs and controls you see depend on your role, the asset's folder access, and your action permissions.

The **Technical & provenance** card and **Embedded Meta Info** tab show read-only file facts. Technical facts include available values such as file type, size, dimensions, duration, codec, folder path, and the recorded original file's SHA-256. Embedded metadata shows metadata stored for or extracted from the file as **Name** and **Value** rows. Custom **Properties**, **Tags**, and **Comments** are application metadata saved with the asset; their controls do not edit the embedded facts or the source file.

## Steps
1. Open **Properties** and review **Technical & provenance**. When **SHA-256** is present, it identifies the recorded original; it is not a fresh hash calculated by reloading this page. The custom property table underneath lists **Name**, **Type**, **Language**, and **Value**. To change a property you are permitted to update, select **Edit**, change its **Name** or **Value**, optionally change **Add to Filter** and **Sort order**, then select **Save**. An existing property's **Type** and **Language** are locked. To add one instead, select **Create Property** and complete the required **Name**, **Type**, **Language**, and **Value** fields.
2. Open **Embedded Meta Info** to inspect the file's metadata. Nested values appear as nested rows. This tab has no edit action; return to **Properties** when you need an editable custom field.
3. Return to **Preview**, expand **Tags**, and use **Choose or Create a Tag**. Select an existing tag or enter a new one to attach it. The tag saves immediately, with no separate **Save** button. Remove an attached tag from the same control to detach it. A tag you remove stays off that asset: adding tags to many files at once, accepting an AI suggestion and later automatic tagging never put it back, and the removed word no longer finds the asset in search. Adding the same tag to that asset again yourself undoes the removal.
4. Open **Comments**. Enter at least two characters under **Add Comment**, then select **Post Comment**. Use **Reply** to add a threaded response. If you have the required permissions, **Edit** and **Delete** appear only on comments you authored; edit the text and select **Save**.
5. For a persistence and byte-integrity check, first use the asset's **Download** action in the Library to download the original file. Calculate that copy's SHA-256 with an independent local hashing tool. Change one permitted custom property's value and attach one tag, then reload the asset. Reopen **Properties** and confirm the new value remains; return to **Preview** and confirm the tag remains. Download the original again, calculate the second copy's SHA-256 independently, and compare the two locally calculated hashes. Do this even when **Technical & provenance** displays a recorded SHA-256; if it does not display one, use the two downloaded copies alone.

## Expected result
Available technical and embedded metadata is readable without becoming editable. The custom property change and tag remain after reload, while the independently calculated hashes of the original downloaded before and after the changes match. Posted comments and replies appear with their author and update time; permitted edits also remain after reload.

## Troubleshooting
If **Embedded Meta Info** says **No metadata available**, no embedded metadata is available to display. Empty technical facts, including a missing recorded SHA-256, are omitted from **Technical & provenance**, and an unavailable aspect ratio is shown as **Unknown**. A missing displayed SHA-256 does not prevent independent verification: hash original downloads made before and after the edit. If **Download** is unavailable, ask an administrator for download permission or for independent byte verification. Add a custom property only if you need an application-managed value; doing so does not add metadata to the source file.

Property names must be 3–100 characters and unique for the asset and language. **Type**, **Language**, and **Value** are required when creating a property, and a new value can contain at most 1,000 characters. Enabling **Add to Filter** requires an integer **Sort order** from 0 through 9,999. A tag is required and can contain at most 100 characters. Extra spaces are removed, matching is case-insensitive, and attaching the same tag twice is rejected. Some words can't be used as tags; such a tag is refused with **This tag can’t be used. Choose a different word.** and is not saved, so choose a different word. A comment or reply must contain 2–1,000 characters.

If a tab or action is absent, or a save is rejected, your account may lack access to the asset or the specific property, tag, or comment permission. Adding and removing tags, and accepting or dismissing AI tag suggestions, need the **Tag assets** permission; without it the tags are shown but can't be changed. You cannot edit or delete another author's comment. Ask an administrator to verify your role and folder grant; a forbidden edit is not applied.
